You are one Ctrl+V away
from leaking a production key.

PasteSafe reads what you're about to paste into an LLM and tells you what would leak — then hands you back a copy with every secret replaced.

What it looks like

$ pbpaste | pastesafe

  CRITICAL aws.access-key-id        1:19
           AWS access key ID
           AWS_ACCESS_KEY_ID=«aws.access-key-id#fba7f486»

  CRITICAL github.pat             2:14
           GitHub personal access token
           GITHUB_TOKEN=«github.pat#0867c742»

  HIGH     pii.credit-card        5:15 verified
           Payment card number
           CUSTOMER_CARD=«pii.credit-card#ed688096»

  CLEAN    nothing else in 4.2 KB

Every secret in the report is already replaced. So is the clipboard version you actually paste. So is the JSON you pipe into your editor. So is the SARIF you upload to a public repo.

Why you don't need to tune it

A linter that cries wolf gets switched off in a week, and then it protects nothing. So every rule that can be checked is checked:

Luhn checksum

Card numbers must actually validate. 4242…4243 never fires.

Mod-10 checksum

Taiwan national IDs must validate against the real algorithm.

Structure decode

JWTs need a decodable header, and expired ones are flagged separately.

Placeholder filter

${API_KEY}, changeme, your_token are never findings.

Use it anywhere

# the clipboard — the path most leaks actually take
alias pbpaste='pbpaste | pastesafe --redact | pbcopy'
alias clip='pbpaste | pastesafe --redact | pbcopy'

# a file you are about to send
$ pastesafe --redact dump.sql | pbcopy

# block the commit, permanently
$ pastesafe --install-hook

# GitHub code scanning
$ pastesafe --sarif --fail-on high . > pastesafe.sarif

The part that actually matters

Redaction is one-way. There is no function in this package that turns a placeholder back into a secret. A bug in redaction can't become a second incident, and no output — not the report, not the JSON, not the SARIF — ever contains the raw value. Each secret gets a stable 8-character hash instead, so the same key in four places collapses to one fingerprint you can correlate without ever seeing it.
